CLI Reference

The typical workflow is: oceanarray init a mooring description and fill it in, oceanarray validate it, run oceanarray process stage by stage and look at the stage files with oceanarray report, then oceanarray run for the whole pipeline (stages 1–3, stack, grid, report) in one command, and oceanarray export to write OceanSITES files. python -m oceanarray works as well as oceanarray.

validate, process, run, report, export, plot and animate take the mooring as the first positional argument, in either of two forms:

  • the path to its *.mooring.yaml, or to the folder holding it — the folder can have any name, and every file is named from the description’s name:;

  • with --proc-dir, the mooring’s name: the folder is {proc_dir}/{name}.

oceanarray run /data/proc/dsG3_1_2026/dsG3_1_2026.mooring.yaml --raw-dir /data/raw
oceanarray run dsG3_1_2026 --proc-dir /data/proc --raw-dir /data/raw   # the same

--only SERIAL ... restricts a command to those instruments (--serial is the old spelling, accepted until 0.7.0). -v (before or after the command name) also prints the processing stages’ debug messages.

Without --force, the stages keep a file that already exists (stage 1 also rewrites one older than its raw file) and the report pages keep one newer than its inputs; add --force to rewrite. oceanarray run rebuilds the stack and grid every time.

Exit status: 0 when the command did its work (process and run also when instruments were left out, unless --strict); 1 when it failed, or validate found an ERROR; 2 for a usage error (an unknown flag, or a missing one such as --raw-dir for stage 1).

The flag lists below are generated from the argument parser (oceanarray.cli.build_parser()), so they cannot drift from the code.

oceanarray validate

Check one or more mooring descriptions for missing fields, unrecognised values and structural errors, including the QC override blocks and the OceanSITES codes (see YAML Configuration Reference). Run it before any processing to catch typos in file_type, a missing hab, a malformed serial number or a misspelt QC threshold.

usage: oceanarray validate [-h] [--proc-dir DIR] [--strict]
                           mooring [mooring ...]

Positional Arguments

mooring

Mooring description(s): a <name>.mooring.yaml, its folder, or a name with –proc-dir.

Named Arguments

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

--strict

Exit 1 on warnings as well as errors.

Default: False

Example

oceanarray validate /data/proc/dsG3_1_2026/dsG3_1_2026.mooring.yaml

Prints every ERROR and WARNING. Exits 1 if any description has an ERROR, or with --strict a WARNING; 0 otherwise.

oceanarray stamp

Mark stage files written before the processing_stage marker existed. Each file is read, the marker for the stage its filename states is added (with a history line saying it was declared, not earned by processing), and the file is rewritten with its data unchanged. A file whose name or existing marker says another stage is refused; a file already carrying the marker is left alone.

usage: oceanarray stamp [-h] [--declare N] files [files ...]

Positional Arguments

files

Stage file(s) to mark

Named Arguments

--declare

Possible choices: 1, 2, 3

The stage the files hold (1, 2 or 3); must match their filenames. Required.

Example

oceanarray stamp /data/proc/dsG3_1_2026/*/dsG3_1_2026_*_stage3.nc --declare 3

Exits with a non-zero status if any file was refused.

oceanarray init

Create a skeleton mooring YAML file with commented template fields for all mandatory metadata and one example entry per instrument type. Edit the file to fill in real values and delete unused instrument blocks. Typically run once, before oceanarray validate.

usage: oceanarray init [-h] --proc-dir DIR mooring

Positional Arguments

mooring

Mooring name, e.g. dsG3_1_2026

Named Arguments

--proc-dir

Cruise-level processed output directory (stub is written to {proc_dir}/{mooring}/).

Example

oceanarray init dsG3_1_2026 --proc-dir /data/proc

Creates /data/proc/dsG3_1_2026/dsG3_1_2026.mooring.yaml (the directory is created if it does not exist).

oceanarray process

Run one or more per-instrument processing stages. Stage 2 requires that stage 1 has already run; stage 3 requires stage 2.

The recommended sequence for a new mooring is:

  1. --stage 1: verify that all raw files are reachable.

  2. --stage 2: check that trimming looks right; adjust deployment_time / recovery_time in the YAML if needed.

  3. --stage 3: apply QC and velocity rotation once stages 1 and 2 are confirmed.

usage: oceanarray process [-h] [--raw-dir DIR] [--proc-dir DIR]
                          [--stage {1,2,3,stack,grid} [{1,2,3,stack,grid} ...]]
                          [--plot] [--summary] [--only SERIAL [SERIAL ...]]
                          [--strict] [--force] [-n]
                          mooring

Positional Arguments

mooring

The mooring: its <name>.mooring.yaml file or its folder (any name), or, with –proc-dir, its name, e.g. dsG3_1_2026 (the folder <proc-dir>/<name>)

Named Arguments

--raw-dir

The cruise’s raw-data folder; a mooring’s raw files are in <raw-dir>/<name>/. Needed only when stage 1 runs.

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

--stage

Possible choices: 1, 2, 3, stack, grid

Stage(s) to run (default: 1 2 3). ‘stack’ and ‘grid’ are deprecated and removed in 0.7.0: ‘oceanarray run’ builds them.

--plot

After stage 2, plot the MicroCAT records (temperature, conductivity, pressure)

Default: False

--summary

Print the number of records per instrument and serial number

Default: False

--only

Process only instrument(s) with these serial number(s), e.g. –only 14321 400118

--strict

Stop at the first failing instrument (exit 1). Without it, stages 1-3 carry on past failed instruments, log them, and exit 0.

Default: True

--force

Rewrite stage files that already exist (default: keep them; stage 1 rewrites only a file older than its raw file)

Default: False

-n, --dry-run

List the stage files each stage would write (new, keep or rewrite) and, for stage 3, which instruments get interpolated pressure; write nothing.

Default: False

Stage descriptions

  • Stage 1: reads raw instrument files via seasenselib and writes {mooring}_{serial}_stage1.nc. Data are stored as-is — no QC, no trimming.

  • Stage 2: trims to deployment_time / recovery_time from the YAML and applies clock drift correction. Writes {mooring}_{serial}_stage2.nc.

  • Stage 3: runs the QC tests (gross range, spike, flat line, tilt; see Automatic QC flagging (Stage 3)), derives salinity, interpolates pressure for instruments without a pressure port, rotates Aquadopp velocities to earth coordinates, and applies magnetic declination correction. Writes {mooring}_{serial}_stage3.nc.

oceanarray run then builds the two mooring-level products:

  • stack: interpolates all instruments onto a common time axis and writes {mooring}_stack.nc. Instruments sampling faster than --dt-seconds are subsampled by nearest-neighbour; slower instruments are interpolated linearly. The 60-second default suits most mooring data; for high-frequency analysis (e.g. internal waves from fast thermistors) work from the _stage3.nc files or build a finer stack with --dt-seconds.

  • grid: interpolates the stack onto a regular pressure grid and writes {mooring}_grid.nc. Values outside the instrument depth range at each time step are set to NaN. QC flags from stage 3 are not consulted — data flagged suspect or bad are treated the same as good unless already NaN.

Output created

Per-instrument: {mooring}_{serial}_stage{N}.nc in {proc_dir}/{mooring}/{instrument}/. Mooring-level: {mooring}_stack.nc and {mooring}_grid.nc in {proc_dir}/{mooring}/.

Examples

Run stage 1 for all instruments:

oceanarray process dsG3_1_2026 --raw-dir /data/raw --proc-dir /data/proc --stage 1

Rerun stage 2 for a single instrument after updating the YAML:

oceanarray process dsG3_1_2026 --raw-dir /data/raw --proc-dir /data/proc --stage 2 --only 26261 --force

See what each stage would write, without writing anything:

oceanarray process /data/proc/dsG3_1_2026 --dry-run

The stack and grid are built by oceanarray run (process --stage stack grid still works, with a note, until 0.7.0):

oceanarray run dsG3_1_2026 --proc-dir /data/proc --stage 3 --dp 10 --pmin 100 --pmax 2000

oceanarray report

Generate HTML reports for a mooring. Without any report-type flags, generates only the mooring summary page. See HTML Reports for a description of what each report page contains.

usage: oceanarray report [-h] [--raw-dir DIR] [--proc-dir DIR] [-o DIR]
                         [--report-dir DIR] [--sig-level SIG [SIG ...]]
                         [--force] [--instruments] [--grid] [--stack]
                         [--only SERIAL [SERIAL ...]] [--all] [--pdf]
                         [--pdf-dir DIR] [--array] [--cruise-table] [-n]
                         [--skip-existing]
                         mooring

Positional Arguments

mooring

The mooring: its <name>.mooring.yaml file or its folder (any name), or, with –proc-dir, its name, e.g. dsG3_1_2026 (the folder <proc-dir>/<name>)

Named Arguments

--raw-dir

The cruise’s raw-data folder; a mooring’s raw files are in <raw-dir>/<name>/. Needed only when stage 1 runs.

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

-o, --output-dir

Directory for the HTML report (default: {proc-dir}/{mooring}/report/)

--report-dir

Central directory for all mooring reports. Each mooring’s pages are written to DIR/{mooring}/ instead of proc/{mooring}/report/, making the whole report tree portable.

--sig-level

σ₀ target values (kg m⁻³, referenced to 0 dbar) for isopycnal height-above-seabed tracking in the grid report. Pass one or more values; they are sorted before use. Example: –sig-level 27.5 27.7 27.9 (default: 27.7).

--force

Overwrite existing report

Default: False

--instruments

Also generate per-instrument HTML pages (slow; skipped by default)

Default: False

--grid

Also generate the gridded-data report page (requires _grid.nc)

Default: False

--stack

Also generate the stacked-data report page with pressure and T time series (requires _stack.nc)

Default: False

--only

Generate per-instrument page(s) for these serial number(s) only (implies –instruments for the listed serials)

--all

Generate all report pages: equivalent to –stack –grid –instruments –pdf (also builds the combined PDF)

Default: False

--pdf

Combine the generated HTML report pages into a single A4 PDF ({mooring}_report.pdf), in reading order summary → instruments → stack → grid. Requires the ‘pdf’ extra: pip install oceanarray[pdf]. Implied by –all.

Default: False

--pdf-dir

Write the combined PDF to DIR/{mooring}_report.pdf instead of beside the HTML pages, so every mooring’s PDF collects in one shareable directory (created if needed). Only affects PDF placement; still needs –pdf or –all to build the PDF at all.

--array

Treat the positional argument as an array YAML path (name ending .array.yaml) and generate an array-level HTML index linking all mooring reports. –report-dir is the output root for the index.

Default: False

--cruise-table

Generate a standalone, print-optimised HTML recovery table for use in cruise reports (one per mooring: {mooring}_recovery_table.html).

Default: False

-n, --dry-run

Show which report files would be generated (no files written).

Default: False

--skip-existing

Skip any page that already exists, even if its files are newer (–force always rebuilds).

Default: False

Output created

{mooring}_report.html (always), plus optional {mooring}_stack_report.html, {mooring}_grid_report.html, and report/instrument/{mooring}_{serial}_report.html.

Examples

Summary and per-instrument pages:

oceanarray report dsG3_1_2026 --raw-dir /data/raw --proc-dir /data/proc --instruments

All report types (equivalent to --stack --grid --instruments --pdf):

oceanarray report dsG3_1_2026 --raw-dir /data/raw --proc-dir /data/proc --all

Array-level index across all moorings:

oceanarray report cruise.array.yaml --array --report-dir /data/reports

Cruise recovery table:

oceanarray report dsG3_1_2026 --raw-dir /data/raw --proc-dir /data/proc --cruise-table

oceanarray run

Run the complete processing pipeline in one command: stages 1, 2, and 3, followed by stack, grid, and all report pages. Continues past individual instrument failures — check the processing logs in {proc_dir}/{mooring}/processing_logs/ for details.

Use oceanarray run only after confirming that stage 1 can read all raw files and that the deployment_time / recovery_time values in the YAML produce the correct trim (verified with oceanarray process --stage 2 and a quick report inspection).

usage: oceanarray run [-h] [--raw-dir DIR] [--proc-dir DIR] [--force]
                      [--only SERIAL [SERIAL ...]] [--stage N [N ...]]
                      [--from N] [--stack-stage N] [-n] [--skip-existing]
                      [--strict] [--dt-seconds SECONDS] [--dp DBAR]
                      [--pmin DBAR] [--pmax DBAR] [-o DIR] [--report-dir DIR]
                      [--sig-level SIG [SIG ...]]
                      mooring

Positional Arguments

mooring

The mooring: its <name>.mooring.yaml file or its folder (any name), or, with –proc-dir, its name, e.g. dsG3_1_2026 (the folder <proc-dir>/<name>)

Named Arguments

--raw-dir

The cruise’s raw-data folder; a mooring’s raw files are in <raw-dir>/<name>/. Needed only when stage 1 runs.

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

--force

Overwrite existing files at every stage

Default: False

--only

Restrict to these serial number(s) for processing and per-instrument reports

--stage

Possible choices: 1, 2, 3

Stages to run before the stack (default: 1 2 3). They must run through stage 3 (stage 2 with –stack-stage 2), so the stack never takes stage files older than the ones just written: –stage 2 3 re-runs stages 2 and 3 without the raw files, –stage 3 re-runs stage 3. To run one stage on its own, use ‘oceanarray process –stage N’.

--from

Possible choices: 1, 2, 3

Start at stage N and run through stage 3 (2 with –stack-stage 2): –from 2 is –stage 2 3.

--stack-stage

Possible choices: 3, 2

Build the stack and grid from the stage-N files (default 3). 2 is a quick look at sea without stage 3: no QC flags, no interpolated pressure, velocities without magnetic declination; the report says so.

Default: 3

-n, --dry-run

List the stage, stack, grid and report files the run would write; write nothing.

Default: False

--skip-existing

Keep any report page that exists, however old (the stage files, stack and grid are not affected).

Default: False

--strict

Stop at the first failing stage (exit 1, no report). Without it the run carries on past failed instruments and a failed stage 3, stacks stage-2 files where stage 3 is missing, and records what was left out; the products are provisional (data_mode P) either way.

Default: True

--dt-seconds

Stack time step, in seconds (default: the description’s stack: block, else 60)

--dp

Grid spacing, in dbar (default: the description’s grid: block, else 20)

--pmin

Shallowest grid level, in dbar (default: the description’s grid: block, else 200)

--pmax

Deepest grid level, in dbar (default: the description’s grid: block, else 1000)

-o, --output-dir

Directory for the HTML report (default: {proc-dir}/{mooring}/report/)

--report-dir

Central directory for all mooring reports. Each mooring’s pages are written to DIR/{mooring}/ instead of proc/{mooring}/report/, making the whole report tree portable.

--sig-level

σ₀ target values (kg m⁻³, referenced to 0 dbar) for isopycnal height-above-seabed tracking in the grid report. Pass one or more values; they are sorted before use. Example: –sig-level 27.5 27.7 27.9 (default: 27.7).

Output created

All stage NC files, {mooring}_stack.nc, {mooring}_grid.nc, mooring summary report, stack report, grid report, and per-instrument reports.

Example

oceanarray run dsG3_1_2026 --raw-dir /data/raw --proc-dir /data/proc --force

oceanarray export

Write a mooring’s stage-3 files and grid as OceanSITES 1.4 files (see OceanSITES export): one deployment file per instrument and one gridded file. The mooring description needs platform_code; --array adds the array’s site_code and project. An instrument that cannot be exported is listed and left out; the command exits 1 only when nothing was written.

usage: oceanarray export [-h] [--proc-dir DIR] [--array YAML] [-o DIR]
                         [--no-grid] [--force] [-n]
                         mooring

Positional Arguments

mooring

The <name>.mooring.yaml, its folder, or a mooring name with –proc-dir.

Named Arguments

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

--array

The <array>.array.yaml; supplies site_code and project.

-o, --output-dir

Where to write the files (default: <mooring folder>/oceansites).

--no-grid

Leave the grid out.

Default: False

--force

Replace OceanSITES files that exist.

Default: False

-n, --dry-run

Convert and list the files that would be written; write nothing.

Default: False

Output created

OS_<platform>_<YYYYMM>_<mode>_<type>-<serial>-<depth>m.nc per instrument and OS_<platform>-<YYYYMM>_<start>-<end>_GRD_<interval>-DP<step>.nc for the grid, in {proc_dir}/{mooring}/oceansites/ (or -o DIR).

Example

oceanarray export dsG3_1_2026 --proc-dir /data/proc --array /data/proc/MIXSED2026.array.yaml

oceanarray list

Print a reference table of allowed instrument: and file_type: values for mooring YAML configuration. Use this to look up the correct reader name for a given instrument type, or to check which instrument: values are recognised.

Does not require a mooring name, --raw-dir, or --proc-dir.

usage: oceanarray list [-h] [{instruments,file-types}]

Positional Arguments

topic

Possible choices: instruments, file-types

Filter output: ‘instruments’ or ‘file-types’ (default: show both).

Example

oceanarray list

Preliminary visualisation commands

The following commands produce standalone plots and animations. They are available for quick inspection but are considered preliminary — the output style, variable names, and flag set may change in a future release.

oceanarray plot

Show an interactive overview plot of processed data, or save it to a file.

usage: oceanarray plot [-h] [--proc-dir DIR] [--var-y VAR_Y]
                       [--var-color VAR_COLOR] [--colormap COLORMAP]
                       [--markersize PTS2] [--downsample-seconds SECONDS]
                       [--output FILENAME] [-o DIR] [--show]
                       mooring

Positional Arguments

mooring

The mooring: its <name>.mooring.yaml file or its folder (any name), or, with –proc-dir, its name, e.g. dsG3_1_2026 (the folder <proc-dir>/<name>)

Named Arguments

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

--var-y

Variable on y-axis (default: temperature)

Default: 'temperature'

--var-color

Variable for scatter colour; omit for line plot

--colormap

Matplotlib colormap (default: RdBu_r)

--markersize

Scatter marker size in points² (default 4). Only used in scatter mode.

--downsample-seconds

Resample interval in seconds (default: 120)

--output

Base filename for saved figure (e.g. overview.png); combined with –output-dir if given

-o, --output-dir

Directory for saved figure (default: mooring proc dir)

--show

Display the figure interactively (works alongside –output)

Default: False

Example

oceanarray plot dsG3_1_2026 --proc-dir /data/proc --var-y pressure --var-color temperature --output overview.png

oceanarray animate

Generate an animated hodograph (tip of the velocity vector tracing a path over time) for Aquadopp or ADCP instruments. Requires east_velocity and north_velocity in the stage 3 output. The Pillow library must be installed for GIF output.

usage: oceanarray animate [-h] [--proc-dir DIR] [--only SERIAL [SERIAL ...]]
                          [--output FILE] [-o DIR] [--u-var VAR] [--v-var VAR]
                          [--lp-days DAYS] [--smooth-hours HOURS]
                          [--frame-hours HOURS] [--fps FPS] [--dpi DPI]
                          mooring

Positional Arguments

mooring

The mooring: its <name>.mooring.yaml file or its folder (any name), or, with –proc-dir, its name, e.g. dsG3_1_2026 (the folder <proc-dir>/<name>)

Named Arguments

--proc-dir

The cruise’s processed-data folder; a mooring’s files are in <proc-dir>/<name>/. With it, MOORING may be just the name.

--only

Serial number(s) to animate (default: all instruments with velocity data)

--output

Output GIF path when one instrument is animated (default: <name>_<serial>_hodograph.gif in –output-dir)

-o, --output-dir

Directory for the GIFs (default: beside each instrument’s stage file)

--u-var

Eastward velocity variable name (default: east_velocity)

Default: 'east_velocity'

--v-var

Northward velocity variable name (default: north_velocity)

Default: 'north_velocity'

--lp-days

Low-pass window for eddy-component removal in days (default: 4.0)

Default: 4.0

--smooth-hours

Tukey smoothing window in hours applied to both panels (default: 3.0)

Default: 3.0

--frame-hours

Time step between frames in hours (default: 6.0 → one frame per quarter-day of deployment)

Default: 6.0

--fps

Frames per second in the output GIF (default: 20)

Default: 20

--dpi

Resolution of each frame in dots per inch (default: 100)

Default: 100

Example

oceanarray animate dsG3_1_2026 --proc-dir /data/proc --only 400115 --output dsG3_400115_hodograph.gif

--basedir DIR (removed)

The --basedir flag has been removed. Passing it prints a migration message naming the replacement and exits without processing. Use --raw-dir and --proc-dir with the mooring-first layout instead.

See Migrating from the --basedir Layout for step-by-step migration instructions.
