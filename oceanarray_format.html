OceanArray Data Format

oceanarray’s shareable output is OceanSITES 1.4 (OceanSITES Data Format Reference Manual), with no departures from it. This page lists what the export writes; OceanSITES export lists the products and file names. The stage, stack and grid files the pipeline works with (*_stage3.nc, *_stack.nc, *_grid.nc) are oceanarray’s own working files and are not OceanSITES files.

Dimensions and coordinates

Manual §2.3–2.4. No coordinate holds a fill value.

Name

Units

Value

TIME

days since 1950-01-01T00:00:00Z

UTC; axis = "T".

DEPTH

m, positive = "down"

Deployment file: the nominal instrument depth (water depth minus height above bottom), or for an ADCP the nominal bin depths. Gridded file: the pressure levels converted with gsw.z_from_p. The comment says which. PRES carries the pressure, so the knock-down is in the data, not in DEPTH.

LATITUDE, LONGITUDE

degrees_north, degrees_east

WGS84 (EPSG::4326), one value, from the mooring description.

Data variables

Manual §2.5 and reference table 6. Every parameter is on (TIME, DEPTH), with coordinates = "TIME DEPTH LATITUDE LONGITUDE", the stage-3 standard_name, units (oceanarray’s canonical spelling), long_name and valid range, and DM_indicator. Deployment files add ancillary_variables, processing_level and the sensor_* attributes (model, serial number, calibration date, mount, orientation, data start and end).

Variables without a code (beam velocities, amplitude, tilt, sigma0) stay in the stage files and are not exported.

Quality control

Manual §2.6 and reference table 2. oceanarray’s flags already use table 2, so a deployment file’s <PARAM>_QC holds them unchanged (byte, conventions = "OceanSITES QC Flags"), with 9 wherever the value is missing. An ADCP’s below-seabed flag, kept apart in stage 3, is merged into each velocity flag where it failed or was suspect (the worse flag is kept). Gridded files carry no _QC variables (§4.2.1).

Data mode

Reference table 4. P (provisional) unless the instrument entry in the mooring description records D after a manual review, which is accepted only when the stage-3 file records the calibration-dip correction. data_mode on the instrument entry is one letter or a mapping from variable name to letter. The global data_mode is the single mode, or M when variables differ. A grid records no per-input modes, so only a P grid is exported.
