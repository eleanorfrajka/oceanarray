Upgrading from 0.6.1 to 0.7.0

Stage files carry clock_offset only when applied

Stage 1 no longer writes a clock_offset of 0 (it applies no clock correction), and stage 2 writes the clock_offset variable only when it applies a non-zero offset. A file with no offset therefore has no clock_offset variable: read it with ds.get("clock_offset", 0) (an absent variable means no offset), not ds["clock_offset"]. Rerun stage 2 to update existing files.

The clock tools moved to analysis

oceanarray.pipeline.clock (offsets, deployment) is now oceanarray.analysis.clock, unchanged. The old path still imports, with a DeprecationWarning, until 0.8.0; change from oceanarray.pipeline.clock import … to from oceanarray.analysis.clock import ….

Depth and pressure conversion moved out of pipeline.pressure

pressure_from_depth and depth_from_pressure are now in oceanarray.physics, and ORIGINATOR_BIN_PRESSURE_ATTRS and originator_bin_geometry in oceanarray.readers.adcp_geometry, unchanged. Importing them from oceanarray.pipeline.pressure still works, with a DeprecationWarning, until 0.8.0; change from oceanarray.pipeline.pressure import pressure_from_depth to from oceanarray.physics import pressure_from_depth.

The mooring YAML modules moved into oceanarray.mooring

Everything about the mooring YAML is now in the oceanarray.mooring package, unchanged. from oceanarray import mooring and oceanarray.mooring.load, check, template, save and the other names work as before.

Mooring YAMLs in their own folder

New in 0.7.0: a paths file, paths.yaml, says where a project’s folders are (Where the folders are: paths.yaml), and the mooring YAMLs live in its yaml_dir, apart from the processed files. oceanarray.Paths.mooring_path and mooring_paths still find a mooring YAML in the processed-data folder, as in the standard structure until now, with a DeprecationWarning, until 0.8.0; move each YAML to its yaml_dir.

The verbs take mooring_path and paths

run, process, report and export take the mooring YAML’s path and an oceanarray.Paths (Where the folders are: paths.yaml), and nothing else about where files are; oceanarray.mooring.load and check take the YAML’s path. Every folder comes from paths: the stage, stack and grid files from paths.mooring_dir(name), the raw files from paths.raw_mooring_dir(name), the pages (and the PDF, beside them) from paths.report_mooring_dir(name), the OceanSITES files from paths.export_dir. A mooring whose folder is not <dir>/<mooring_name> gets it from paths.with_mooring. Change

oa.run("proc/M2_2016/M2_2016.mooring.yaml", raw_dir="raw")

to

paths = oa.Paths(raw_dir="raw", proc_dir="proc")
oa.run("proc/M2_2016/M2_2016.mooring.yaml", paths)

The old forms still work, with one DeprecationWarning naming the new call, until 0.8.0, and write the same files to the same folders as before: a verb called without paths works in the folder holding the YAML (mooring_dir=, the mooring’s own folder, overrides it), its raw files in <raw_dir>/<that folder's name>, its pages in <folder>/report (the recovery table in the folder itself), its OceanSITES files in <folder>/oceansites. A mooring folder or a loaded mooring YAML (a dict) given in place of the path, and the first argument given as mooring=, warn the same way. The command line is unchanged.

One base for the package’s errors

Every error oceanarray raises now derives from OceanarrayError (MooringError, ReaderError, StageError, UnitsError, OceanSitesError, CaldipError, LegacyLayoutError); each keeps its built-in base, so except ValueError still works. A file a reader cannot read raises ReaderError, and a problem in the mooring YAML found while processing raises MooringError; both were a plain ValueError. StageError is no longer a MooringError: code that caught a wrong-stage file with except MooringError should catch StageError or OceanarrayError. StageError and ValidationIssue are defined in oceanarray.exceptions; import them from there (or StageError from oceanarray).

Data warnings are log records

Problems found while reading or reporting (records dropped for a missing time, unexpected units, a stage file without its marker, an attribute dropped on writing) were Python UserWarning s; they are now WARNING records of the oceanarray logger, so they also reach the stage log files. Code that caught them with warnings.catch_warnings or pytest.warns should read the log instead (caplog in pytest). Deprecations are still DeprecationWarning s.

A missing folder or mooring YAML raises

MooringReport.generate and generate_recovery_table returned None, and Stage2Processor / Stage3Processor.process_mooring returned False, when the processing folder or the mooring YAML was missing, printing the reason. They now raise MooringError with the path in the message. Replace a check for None or False with except MooringError. The oceanarray commands already stopped with an error; only the message changes.

No pitch or roll flags

Tilt QC is on the geometric tilt only (QC_TILT, overridden by tilt_qc), so qc_ranges: pitch / roll are no longer applied and stage 3 writes no pitch_qc / roll_qc; the stack no longer carries them. A mooring YAML that still sets them gets a warning; remove them, and set tilt_qc to change the thresholds.

Grid levels are pmin_dbar and pmax_dbar

A grid file now records its pressure range as pmin_dbar and pmax_dbar (with dp_dbar, unchanged), the same words as pmin/pmax in the YAML, the call and the CLI. Grids written before carry p_start_dbar / p_end_dbar; oceanarray still reads them (pages, the check whether a grid is current), but code of your own that reads these attributes should read the new names, falling back to the old ones for older files. The default levels (200 to 1000 dbar every 20 dbar) moved from oceanarray.pipeline._run.DEFAULTS, which is gone, to oceanarray.config.parameters: GRID_PMIN_DBAR, GRID_PMAX_DBAR and GRID_DP_DBAR (and STACK_DT_SECONDS for the stack’s time step).
